Sales ↔ Marketing · 15 Nov 2026 · with Yegor's answers

Why this changes

Yegor pushed back on 12 Nov, and he is right. What was built is a CRM: every rep, every inbox, every chat, one timeline per customer. That is more personal data than marketing needs, and it still does not answer the question he expected: which content brings customers who buy.

The new aim, in Henry's and Yegor's words:

  • Social media → sales: when someone comes from a YouTube Short, a long video, Instagram, a comment or a DM and contacts us or buys, we see it. This is our biggest blind spot today.
  • What customers talk about: questions before buying, pain points, issues, products, what makes people hesitate, as summaries for marketing.
  • Both ways: sales sees which content actually sells, so they can send it.

The rule that follows: CTRL keeps topics and totals, not people's messages. No customer names on the page. Email and WhatsApp text is read once by the AI for its questions and topics, then thrown away.

How social media → sales is tracked

1. One link system, no raw links anywhere

Every link anyone at OneMiners posts becomes a short tracked link from CTRL, on our own address (for example go.oneminers.com/z15-yt). Each one carries a code that says exactly where it was posted: the platform, the post, and whether it sat in a bio, a description, a comment reply or a DM. CTRL counts every click, then sends the person on to where they wanted to go.

The team rule: never paste a raw website link or a raw WhatsApp number again. CTRL adds the tracked link by itself to every post it prepares or publishes. For comments and DMs, the team gets a short list of ready reply links per platform (Instagram DM, YouTube comment, TikTok DM and so on), one tap to copy.

2. Where the links go, platform by platform

3. Rep links: the same system for the sales team

Each salesperson has their own code. When Slávek sends a customer a link to a product, the link carries his code, e.g. go.oneminers.com/r-slavek-z15-pro. CTRL then shows, per rep, how many of their links were clicked, how many led to a conversation, and how many to an order. It is the same link maker with one more source next to platform and post, and it holds no customer data. A full CRM with customer records, call recordings and emails is a separate, later project.

5. Joining it up

CTRL follows each code to the conversation it started, then matches that customer's email or phone across Sales Inquiries, Support Requests, Technical, Orders, the shop orders, the three inboxes and the support WhatsApp. The result is one path per customer: which post → which conversation → which ticket or inquiry → order or not. The page shows only the totals of those paths, never the people.

Honest limits: counting starts on the day the links go live, never backwards. A customer can delete the code from the typed WhatsApp message, or type our address by hand; then the "where did you find us?" answer is the fallback, and the page shows the share of unknown source openly instead of hiding it. Shorts and TikTok captions can't hold links, so those are tracked per channel, not per video, unless the customer names the video.

How an inquiry counts as won, open or lost (proposed rule, Yegor to confirm)

ClickUp statuses are used differently by different people, so the rule does not depend on them. It uses two things CTRL can see for certain: an order, and whether anything has happened.

Result Rule
Won The same email or phone appears in an Orders task, or in the shop's order feed, within 90 days of the inquiry
Open No order yet, and the task had a reply, comment or status change in the last 30 days
Lost No order, and nothing has happened on the task for 30 days, or it was closed without an order

A lost inquiry that orders later moves to Won by itself. The 90 and 30 days are settings and can be changed after a month of real numbers.

For Tomáš H: the short address

oneminers.com and CTRL sit in different Cloudflare accounts, so the simplest way needs no account sharing. In the oneminers.com zone:

  1. DNS → Add record: type AAAA, name go, address 100::, Proxied (orange cloud) on.
  2. Rules → Redirect Rules → Create rule: name it "Tracked links". When the hostname equals go.oneminers.com, then URL redirect, type Dynamic, expression concat("https://go.oneminersmarketing.com", http.request.uri.path), status 302, preserve query string off. Deploy.

That's all. A click on go.oneminers.com/ig-bio-wa then reaches CTRL's link Worker, which counts it and sends the person on. If he'd rather attach the link Worker to oneminers.com directly, he can instead invite henry@oneminers.com to the oneminers.com account with the Workers Routes permission.

For Alex: the website and the order feed

1. Keep the code (every page). When a page opens with ?ref=CODE in the address (lowercase letters, digits and dashes, at most 48 characters), save it in a first-party cookie om_ref for 30 days; a newer code replaces it. Also save the first one in om_ref_first if that cookie is empty. Our links also add standard utm_source, utm_medium and utm_campaign tags, so Google Analytics sees the same split. These cookies should sit under the site's existing analytics or marketing consent. When a visitor declines, the code isn't kept, and they show up as "unknown source".

2. The inquiry form. Add a hidden field Ref filled from om_ref, and a visible, optional question "Where did you find us?" with these choices: YouTube, YouTube Shorts, Instagram, TikTok, Facebook, X, LinkedIn, Google search, a friend or colleague, other. Both go onto the ClickUp Sales Inquiries task, as custom fields or as two lines in the description ("Ref: …", "Found us: …"). CTRL's sync reads either.

3. The order feed (permanent data link). When an order is placed, and again when it is paid, cancelled or refunded, the platform sends one small message to CTRL:

POST https://ctrl.oneminersmarketing.com/api/ingest/sales/order

{
  "order_id": "…",            // the platform's own order number
  "at": "2026-11-20T14:03:00Z",
  "status": "placed | paid | cancelled | refunded",
  "ref": "ig-bio-wa",         // om_ref at checkout, or null
  "ref_first": "yt-desc-…",   // om_ref_first, or null
  "products": [{"type": "asic | hosting | other", "model": "Antminer S21 XP", "qty": 2}],
  "email_sha256": "…",        // SHA-256 of the email, trimmed and lowercased
  "phone_sha256": "…"         // SHA-256 of the phone in +countrycode digits form, or null
}

No prices, amounts, names or addresses are sent. The email and phone arrive only scrambled (hashed), which is enough for CTRL to match an order to the inquiry or chat that came before it. CTRL scrambles the ClickUp emails the same way. Henry creates the access key for this feed: a Cloudflare service token plus a CTRL key, sent to Alex privately. Each message is answered with {"ok": true}, and the same order sent twice is stored once.
